# BRC-233: Subject BEEF

David Case (david.case@shruggr.cloud)

## Abstract

**Subject BEEF** is [Atomic BEEF](./0095.md) in shape (a prefix and a subject transaction id in front of a [BRC-62](./0062.md) / [BRC-96](./0096.md) BEEF) without BRC-95's restriction to the subject's ancestors. The subject names which transaction the bag is about. Anything else in the bag is allowed: a profile decides what must be present.

## Specification

| | Atomic BEEF ([BRC-95](./0095.md)) | Subject BEEF (this BRC) |
|--|----------------------------------|--------------------------|
| Prefix (4 bytes) | `0x01010101` | `0x5bb7beef` (provisional) |
| Subject | TXID (32 bytes) | TXID (32 bytes) |
| Body | BEEF | BEEF (BRC-62 / BRC-96 rules only) |
| Graph | Ancestors of the subject transaction | Any transactions |
| Fail if | Subject tx missing, or unrelated txs present | Subject tx missing |

```
5bb7beef                                                 // prefix
2222222222222222222222222222222222222222222222222222222222222222 // subject TXID
0200beef                                                 // BEEF V2 (example)
...
```

## Notes (informative)

* A reader MUST NOT apply BRC-95's ancestor rule or strip transaction bodies from a Subject BEEF. Re-encoding it as Atomic BEEF may drop transactions a profile requires.
* Completeness is profile-defined (e.g. [BRC-176](../tokens/0176.md)). Subject BEEF alone says only which transaction is the subject.
* The distinct prefix lets a strict Atomic BEEF reader fail cleanly instead of rejecting a valid bag as malformed Atomic BEEF.
* For a subject output rather than a transaction, use [Outpoint BEEF](./0158.md).
