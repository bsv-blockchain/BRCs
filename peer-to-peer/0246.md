# BRC-246: Session Upgrade

Brandon Cryderman / HandCash (brandongcryderman@gmail.com)

**Status:** Draft (proposed number, not a BSVA assignment)

## Abstract

This BRC defines a **session upgrade** for [BRC-33](./0033.md) messagebox traffic. The identity key remains the address. A signed, short-lived IPv6 endpoint may ride in a messagebox message so two wallets that are both online can move the rest of that session onto a mutually authenticated socket.

The messagebox stays the rendezvous and the offline inbox. The socket is an optimization of the hot path. It never carries custody. Funds stay on the chain.

## Motivation

A messagebox exists because the other wallet is often offline, firewalled, or unable to keep a listener. That does not mean two live wallets should keep a store-and-forward hop on every chat line and every remittance card.

A naive "try the address first, then the box" stalls the send on a filtered port. This BRC races a short dial against the box, fails through immediately when the network refuses the connect, and never publishes a home address in a handle record.

## Specification

### Scope

This protocol applies to grade-B delivery: chat, remittance cards, and other facts already sent with [BRC-33](./0033.md). It does not apply to coin selection, signing, or broadcast. A conforming wallet MUST still treat an on-chain output as the only proof of payment or of item custody.

Out of scope: IPv4, NAT traversal, hole punching, and publishing an endpoint in [BRC-169](./0169.md) resolve.

### Endpoint offer

An offer is a UTF-8 body:

```
handcash-session-offer:{"v":1,"host":"2001:db8::1","port":3342,"identityKey":"<hex>","counterparty":"<hex>","expiresAt":0,"nonce":"<32 hex>","signature":"<64-byte compact hex>"}
```

| Field | Rule |
|---|---|
| `host` | Global unicast IPv6 (`2000::/3`). Link-local, ULA, loopback, and IPv4-mapped addresses MUST be rejected. |
| `port` | 1–65535. The port is in the offer. It is not a well-known port. |
| `identityKey` | Compressed public key of the signer, lowercase hex. |
| `counterparty` | The only identity that may dial this offer. |
| `expiresAt` | Unix milliseconds. Lifetime MUST NOT exceed 60 seconds. |
| `nonce` | 16 random bytes, hex. |
| `signature` | Compact secp256k1 (r‖s, 64 bytes, hex) over the preimage below. SHA-256 is applied by the signer, as in Bitcoin message signatures. |

Preimage (UTF-8, newline-separated):

```
session-upgrade
offer
{identityKey}
{counterparty}
{host}
{port}
{expiresAt}
{nonce}
```

A wallet MUST NOT place this object in a handle record, a BRC-169 resolve response, or any public directory. It MAY place it in a BRC-33 `sendMessage` body addressed to `counterparty`, and only while a listener is bound to that host and a local accept on that address succeeded.

A listener that dies MUST stop emitting offers. A local accept does not prove that a remote firewall allows inbound. The completed handshake is the proof that this peer can reach the endpoint.

Receivers MUST ignore an offer whose `counterparty` is not their identity key, whose signature fails, or whose `expiresAt` has passed. They MUST NOT show the body as chat.

### Who dials

The lexicographically smaller identity key (lowercase hex) is the dialer. The other side only listens. This keeps one socket.

### Race

When the dialer holds an unexpired offer and no live session:

1. Start a connect to `host`/`port` with a budget of **300 ms**.
2. `ECONNREFUSED`, `ENETUNREACH`, `EHOSTUNREACH`, `EADDRNOTAVAIL`, `ENOTFOUND`, and `ECONNRESET` fail through immediately. Drop that offer. Deliver this message on the messagebox. Do not wait out the budget.
3. If the handshake does not finish within 300 ms, deliver this message on the messagebox and do not also send it on a socket that connects later. A late handshake MAY be kept for the next message.
4. If the handshake finishes within the budget, send this message on the socket and do not post it to the messagebox.

A timeout MUST NOT block the send.

### Handshake

Length-prefixed frames: 4-byte big-endian length, then UTF-8 JSON. A frame larger than 256 KiB MUST be rejected. A payload larger than 256 KiB MUST stay on the messagebox.

The dialer sends `hello`. The listener answers `welcome`. Both signatures use the same compact form as the offer.

Hello preimage:

```
session-upgrade
hello
{speaker}
{offer.identityKey}
{offer.host}
{offer.port}
{offer.nonce}
{helloNonce}
{timestamp}
```

`speaker` MUST equal `offer.counterparty`. The listener MUST verify the offer signature and that the offer names the listener as `identityKey`.

Welcome preimage:

```
session-upgrade
welcome
{speaker}
{peer}
{host}
{port}
{helloNonce}
{welcomeNonce}
{timestamp}
```

`speaker` MUST equal `offer.identityKey`. `helloNonce` MUST equal the hello just received. Timestamp skew MUST NOT exceed 60 seconds.

After both sides accept, the socket is hot. Later messages to that identity go on the socket. Each message is `{ "t": "msg", "id": "<id>", "body": "<the same string the box would have carried>" }`. The receiver MUST ack `{ "t": "ack", "id": "<id>" }` once the body is accepted into the same ingest path as an inbox message. No ack within 300 ms drops the session and that message falls back to the messagebox.

If the socket closes, the next message uses the messagebox. A new offer is required before another dial.

### What this is not

- Not a replacement for BRC-33. The first contact, an offline peer, and a failed dial stay on the box.
- Not a custody channel. A socket ack is not a payment.
- Not device parity. Two installs of one phrase are a different problem. This session is between two identity keys.
- Not a phone requirement. A platform that cannot keep a listener simply never emits an offer. It can still dial.

## Implementation

HandCash Desktop: `src/wallet/directSession/` and `electron/directSessionServer.ts`. The listener binds one global IPv6 address on an ephemeral port after a local accept, and only then may the wallet attach an offer to a box send.
